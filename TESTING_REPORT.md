## 3. JavaScript API ⚠️

### Результаты:
```javascript
{
  hasFilamentHub: true,
  filamentHubFunctions: ["navigate"],
  hasWx: false,
  wxFunctions: []
}
```

### Обнаружено:
- ✅ `window.filamenthub` существует в браузере
- ✅ Функция `navigate` доступна (добавлена через frontend код)
- ❌ `window.wx` не существует в обычном браузере (ожидаемо, это API OrcaSlicer WebView)
- ❌ Функции экспорта (`exportFilamentPresets`, `exportPrinterProfiles`, `exportPrintProfiles`) не доступны в браузере (ожидаемо, добавляются C++ кодом)

### Объяснение:
JavaScript API функции экспорта добавляются через C++ код в OrcaSlicer при загрузке WebView. В обычном браузере они недоступны, что нормально. Они будут доступны только когда:
1. Frontend загружен в OrcaSlicer WebView
2. C++ код выполнил `WebView::RunScript` с JavaScript кодом из `OnLoaded` callback

## Что нужно протестировать в реальном OrcaSlicer:

### Критично:
1. **Авторизация через WebView:**
   - Вход через форму логина
   - Сохранение токена в AppConfig
   - Автоматическая синхронизация после логина

2. **Синхронизация пресетов:**
   - Полная синхронизация (force_full_sync = true)
   - Инкрементальная синхронизация
   - Импорт новых пресетов
   - Обновление существующих пресетов

3. **Экспорт пресетов:**
   - `window.filamenthub.exportFilamentPresets()` - экспорт пресетов филамента
   - `window.filamenthub.exportPrinterProfiles()` - экспорт профилей принтера
   - `window.filamenthub.exportPrintProfiles()` - экспорт профилей печати

4. **Обработка ошибок:**
   - 401 (истечение токена)
   - 403 (нет разрешений)
   - 500 (ошибка сервера)

### Важно:
5. **Маппинги:**
   - Сохранение маппингов в AppConfig
   - Загрузка маппингов при старте
   - Обновление маппингов при синхронизации

6. **UI состояния:**
   - Кнопка синхронизации (активна/неактивна)
   - Прогресс-бар
   - Уведомления в WebView
